# 无蒙古文转写专家条件下的替代研究方案：页面级版面分析主线

更新时间：2026-05-10

## 1. 问题背景

当前页面级数据已经完成了文本列框、阅读顺序、方向和 ignore 区域标注，但没有蒙古文专家能够完成手写传统蒙古文的列级转写。因此，严格的 OCR 识别指标（CER/WER）暂时无法作为主实验指标。

当前标注状态：

| split | pages | TextColumn boxes | ignored boxes |
| --- | ---: | ---: | ---: |
| train_unlabeled | 43 | 660 | 84 |
| val | 8 | 108 | 19 |
| test | 11 | 163 | 50 |
| total | 62 | 931 | 153 |

所有有效文本列的 `transcript` 字段当前为空，因此不能把现有识别输出当作可验证 OCR 准确率。

## 2. 研究主线调整

原计划主线是“页面级端到端 OCR”，需要列级转写作为 CER/WER ground truth。现阶段建议调整为：

> **传统蒙古文历史档案的页面级文本列检测、方向处理与阅读顺序恢复。**

这一路线不依赖蒙古文转写专家，仍然具有明确研究价值：历史档案 OCR 的前提是将整页复杂扫描图分解为可靠的文本列，并恢复可读顺序。对于竖排、手写、退化、带印章和扫描方向不一致的传统蒙古文档案，版面分析本身就是难点。

## 3. 当前可报告贡献

1. 构建了传统蒙古文历史档案页面级标注协议，包含文本列框、阅读顺序、方向和 ignore 区域。
2. 清理并排除了中文手写档案页，处理了横向/倒置扫描页，形成 62 页页面级数据。
3. 建立了规则法 baseline 与轻量 YOLOv8n 学习式检测器。
4. 引入 rotation-aware reading order，使旋转重标页的阅读顺序能够正确恢复。
5. 在独立 test split 上证明 YOLOv8n 明显优于规则法。
6. 端到端 OCR pipeline 已经跑通到“列裁切与识别模型推理”阶段，但不报告 CER/WER。

## 4. 主实验结果

采用项目统一 IoU@0.5 贪心匹配口径评估：

| method | Precision | Recall | F1 | Mean IoU | Reading-order accuracy |
| --- | ---: | ---: | ---: | ---: | ---: |
| Rule proposed | 0.680 | 0.509 | 0.582 | 0.831 | 0.907 |
| YOLOv8n + rotation-aware order | **0.919** | **0.626** | **0.745** | 0.767 | **0.920** |

说明：YOLOv8n 显著提高 precision 和 F1，说明学习式检测器能有效减少背景噪声、边缘阴影和伪列误检。规则法在成功匹配的框上 Mean IoU 更高，但召回不足。

## 5. 阈值敏感性

阈值在 val split 上选择，避免直接使用 test 调参。val F1 在 0.35 达到最高，因此主结果采用 `score_threshold=0.35`。

| YOLO score threshold | Val Precision | Val Recall | Val F1 |
| ---: | ---: | ---: | ---: |
| 0.25 | 0.746 | 0.787 | 0.766 |
| 0.30 | 0.812 | 0.759 | 0.785 |
| 0.35 | **0.876** | 0.722 | **0.792** |
| 0.40 | 0.873 | 0.639 | 0.738 |

正式论文中建议主表报告 val-selected threshold 0.35，同时在补充表中说明 0.25--0.35 区间存在 precision-recall trade-off。

## 6. Failure analysis 写法

建议把 failure cases 作为论文重要分析，而不是缺陷回避：

- **少列页面漏检**：例如 `80-48-69-4` 在 0.35 阈值下候选被过滤，说明固定阈值对短页/少列页不够鲁棒。
- **长框过合并**：规则法容易把多段短文本合并为长框，导致 FP/FN 同时增加。
- **旋转页阅读顺序**：横向或倒置扫描需要显式方向处理，否则排序方向会错误。
- **印章与背景噪声**：红印章、纸张污渍和边缘阴影会诱发伪列。
- **异质档案混入**：中文手写档案页必须在数据清理阶段排除，否则会污染训练和评估。

## 7. 端到端 OCR 部分的安全表述

可以保留以下表述：

> We further implemented a recognition-ready page-level pipeline that exports oracle and automatically detected column crops and connects them to an existing recognizer checkpoint. Since expert transcription of handwritten traditional Mongolian columns is currently unavailable, CER/WER is not reported in this study; instead, we focus on the upstream layout analysis metrics required for reliable full-page OCR.

不要写：

- “端到端 OCR 已达到某某 CER/WER”；
- “识别结果经人工验证”；
- “伪转写可作为 ground truth”。

## 8. 后续若获得专家资源

只需补充很小规模的专家转写即可扩展当前工作：

1. 选择 test split 中 3--5 页；
2. 对每个 TextColumn 填写 `transcript`；
3. 复跑 `run_end_to_end_ocr_experiment.py`；
4. 报告 Oracle crop vs YOLO detected crop 的 CER/WER 差距；
5. 将识别实验作为补充，而不是推翻当前版面分析主线。

## 9. 投稿定位建议

当前版本更适合投向 document analysis / digital heritage / historical document processing 方向，强调：

- low-resource historical document layout analysis；
- vertical cursive script column detection；
- reading-order recovery for rotated archival pages；
- reproducible page-level annotation and evaluation without requiring text transcription。
